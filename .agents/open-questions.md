# Open questions

Two lists. The first is what Hong decides for this repository. The second is what the Wriven side must have before integration can happen; those are conditions in the [host protocol](specs/host-protocol.md), not work for this repository. Dated 2026-11-03; remove an item only when its answer is recorded in a linkable place.

## For Hong (this repository)

1. **Developer ID.** Public releases need notarization, which needs a paid Apple developer account; today the machine has only an Apple Development identity. Until then builds are ad-hoc signed and developer-only. Decide whether and when to get one. ([packaging-and-release](specs/packaging-and-release.md))
2. **`collect` as the eleventh component.** Added during spec writing because the feed example cannot make one model call for many items without it. Confirm, or name an alternative. ([pipeline-format](specs/pipeline-format.md), grilling decision 4)
3. **Concurrent runs.** The spec says one run at a time per engine. Should "Run now" be allowed to run alongside a scheduled run of another stream? ([architecture](specs/architecture.md#open-points))
5. **`run_all` missed policy.** Keep it in v0 or drop it since `runs_per_day` already bounds it. ([scheduling](specs/scheduling.md#open-points))
6. **Memory ceiling.** 512 MB RSS per run process was a placeholder. Peak RSS measured 2026-11-03 on a Mac15,7, macOS 27.0.1, Bun 1.4.3, through the private protocol with fixtures: the example at 3 feeds of 100 KB, 35 MB; 20 feeds of 2 MB, 365 MB; 20 feeds of 5 MB (the format's ceiling), 827 MB, so a pipeline at the very ceiling is killed with `memory_limit`. Recommendation: keep 512. ([architecture](specs/architecture.md#open-points))
7. **Query strings in approval sentences.** Add "URLs contain query strings" to the rendering when any `http_fetch` URL has one. Small; proposed in [threat-model](specs/threat-model.md) T1.
8. **Returning the pipeline to the model.** Whether `workflow_get_stream` returns the full pipeline or only sentences. Current answer: full pipeline. ([agent-surface](specs/agent-surface.md#open-points))
9. **Registry publication.** GitHub releases only, or also npm/JSR. Not needed for Wriven. ([packaging-and-release](specs/packaging-and-release.md#open-points))

11. **Developer tooling.** Bun is pinned at 1.4.3, what this machine has, and its test runner names itself `1.4.3-canary.1`. x64 builds have never been executed here because Rosetta is not installed. Decide whether to upgrade Bun and install Rosetta before a first release. ([packaging-and-release](specs/packaging-and-release.md))

12. **Credentials for the example host's live run.** [example-host-03](tickets/example-host-03-live-run.md) needs an API key or an `ant auth login` profile on this machine, and a go-ahead for a few cents of spend. ([example-host](specs/example-host.md) decision 9)

## For the Wriven side (preconditions for integration)

Each item is a condition this design assumes about the host. Where Wriven already recorded a decision, it is linked. All read from the wriven-desktop repository on 2026-11-03.

1. **Client-side tool loop** for at least one provider, with Stop, error, Regenerate and quit semantics consistent with "Interrupted replies". Wriven has none today; it is a separate intent ([client-side-tool-loop.md](https://github.com/and1truong/wriven-desktop/blob/main/.agents/inbox/2026W45/client-side-tool-loop.md)). The engine's tools need: Anthropic `tool_use`/`tool_result` with full content echo; Gemini `functionCall` with `thoughtSignature` echo (measured there: omitting it → 400); OpenRouter `tool_calls` echo with `reasoning_details`. See [agent-surface](specs/agent-surface.md#encoding-per-provider).
2. **Approval UI** (Wriven P3-6) that shows the engine's sentences, calls `stream.approve` with the hash on yes, and handles `pending_approval` after a widening update with the diff. Approval happens on create and on widening edits, not per run (Wriven sidecar decision 13).
3. **`host.llm` implementation**: choose provider and model (the ones the person picked for the automation), call the provider, return text and usage, honour the idempotency key (store replies per key for the run's lifetime), count calls per run against the approved `llm_calls_per_run`, map provider failures to the typed error kinds (`credentials_missing`, `credentials_rejected`, `quota_exhausted`, `rate_limited`, `provider_unavailable`, `provider_refused`), answer `$/cancel`. Wriven's `CredentialsError` has only `missing` and `rejected` today; 429 is a message string. ([host-protocol](specs/host-protocol.md#typed-errors))
4. **Usage and cost** (Wriven P1-3). Without it `llm_reports_cost: false` and the cost cap is "not enforceable"; the call cap still works.
5. **`host.result` implementation**: create a thread (or whatever a result becomes) with the run's `scheduled_for`/`started_at` rather than the time of the call (Wriven's `append` stamps call time), honour the idempotency key, return a `ref`. Store the run report; expose `workflow_list_runs` as a host tool if desired.
6. **State directory**: a `0700` directory the engine owns, under Wriven's data directory. Not Wriven's SQLite.
7. **Clock**: Wriven declares `clock: host` and triggers runs with `scheduled_for`. Wriven's scheduler and missed-run policy are Wriven's (daily/weekly, run once for the most recent missed occurrence on open). `schedule.preview` is available if Wriven wants cron later.
8. **Where the engine binary lives.** Wriven is a bare executable with no `.app` bundle; there is no place "inside" it for a 60 MB binary yet. Options in [packaging-and-release](specs/packaging-and-release.md#installation-by-a-host). Related: Wriven's `PATH`-under-Finder limitation applies to a user-installed engine.
9. **Process handling**: `ProcessRunner` is written for short request/response processes and stops with `SIGKILL` only (read in Wriven's code). The engine is long-lived for the app's lifetime and needs stdin closed (not killed) for a clean drain; the `onLine` reader must not block on engine→host requests.
10. **Single instance.** Wriven has no single-instance lock. The engine refuses a second `initialize` on the same `state_dir` with `conflict`; Wriven must handle that (or add a lock of its own).
11. **Result display**: results contain model output derived from untrusted web content; show them as content, never auto-act on them, and be aware that continuing a result thread with a tool-capable provider exposes that provider to injected text (Wriven already accepted this for Codex in scheduled-actions decision 9). ([threat-model](specs/threat-model.md) T2)
12. **Running while the app is closed** is not supported by this design. If Wriven ever wants it, a host-side headless mode (`--run-scheduled` or a helper sharing `WrivenCore`) would spawn the engine; Wriven's own tests found Keychain access survives headless only with a stable signature, `codex` does not run under `launchd`, and `SMAppService` needs a `.app`. All of that is Wriven's, and none of it is in v0.
13. **Reopen condition.** Wriven's own rule for picking this up: "đặt lịch bằng lời đã chạy thật, và có một tác vụ cụ thể mà schema hẹp không diễn đạt được" (sidecar decision 8). This repository is built so it is ready when that happens; it does not change that rule.
