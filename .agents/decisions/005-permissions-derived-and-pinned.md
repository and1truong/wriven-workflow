# ADR 005: Permissions are derived from the pipeline and pinned at approval, never declared by the agent

Date: 2026-11-03. Status: accepted (Hong, grilling decision 7).

## Context

The brief's principle 1 says the permissions part of a pipeline must translate mechanically into English for approval. Wriven's sidecar grilling (decision 13) went further: the approval text is generated by code from the config, the model never writes it, and request counts are caps the host enforces rather than estimates. A permissions block written by the agent would reintroduce the thing both rules exclude: text the model controls that the person trusts.

## Decision

- The pipeline format has no permissions field. `pipeline.validate` and `stream.create` compute a canonical permissions object from the components and limits, hash it, and render it into fixed English sentences.
- Approval pins the hash. `stream.approve` requires the exact hash. `stream.update` compares new permissions with pinned ones field by field; a subset applies immediately, anything else returns to `pending_approval` with an added/removed sentence diff. Schedule changes always re-approve.
- The same object drives enforcement: proxy allowlist and Seatbelt profile at run start, call caps in the executor.
- The rendering always states denials and the sandbox status.

## Consequences

- There is nothing for the agent to lie about or forget; validation has no "declared ⊇ needed" check to get wrong.
- The host can render its own words from the object, in its own language, and still be correct; the engine's sentences are a correct default and a test fixture.
- Adding a component means adding its derivation rule and sentence; the component table in [permissions](../specs/permissions.md) is the checklist.
- Hash stability is a maintenance duty: new fields enter canonical form only with non-zero values, and a `version` bump forces every stream to re-approve with an explanation.
- A capability that cannot be derived from config (because it would depend on runtime data) cannot exist in this design. That is intended: it is the same rule that forbids runtime-computed URLs.
